# De-orbit & Re-entry Implementation Plan (Phase 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the de-orbit handoff into a real fiery re-entry — the capsule glows plasma-bright, survives if it has a heat shield, and splashes down in the ocean under a parachute — as a bonus recovery on top of the already-won mission.

**Architecture:** Reuse the existing side-view re-entry machinery. A new Heat Shield part gates the nose-temp burn-up RUD; the parachute gives a soft ocean splashdown (new `splashed` status). Real exponential drag bleeds off orbital speed and drives the heating; the render adds an ocean scene + plasma streak. Auto flies it; Manual gets a deploy-chute button that rips if popped too fast.

**Tech Stack:** Vanilla JS ES modules, no build. Physics tested headlessly via `node js/sim.test.js` (node:assert). UI verified in a browser via a no-store `python3 -m http.server`.

---

## File Structure

- `js/parts.js` — new `heatShield` part; `normalizeRocket` gains `hasHeatShield`.
- `js/config.js` — `CHUTE_SAFE_SPEED`, `CHUTE_DRAG`; heat-shield mass lives in parts.
- `js/sim.js` — split the RUD (burn-up gated on heat shield); reconciled re-entry deceleration; `chuteRipped`; auto-safe chute deploy; `deployChute` action; `splashed` terminal status + `crashReason` values.
- `js/missions.js` — recovery milestone/mission check `splashed`.
- `js/main.js` — re-entry result messages; `splashed` treated as a clean landing; recovery sfx; Manual Deploy-Chute button.
- `js/render.js` — ocean scene, plasma streak, splash plume.
- `js/sim.test.js` — re-entry assertions + a recovery-capable build reaching orbit.

Build order: physics (1–2, TDD) → recovery-build tuning (3, TDD) → messages/missions (4) → ocean render (5) → Manual button (6) → verify+deploy (7).

## Notes for the implementer

- **Reuse, don't rebuild.** Re-entry is the existing side view; the heat-RUD is the burn-up; the heat glow is the plasma; the parachute drawing already exists. New work is the shield gate, ocean scene, splash, `splashed` status, and the recovery build.
- **Numbers are knobs.** `heatShield.mass`, `CHUTE_SAFE_SPEED`, `CHUTE_DRAG`, `CHUTE_ALT`, `CRASH_SPEED`, and the `RECOVERY_ROCKET` parts are calibration — tune to green, then playtest the feel.
- **Re-entry is a bonus.** Burn-up / hard-splash lose the capsule but never the mission (orbit + deploy already scored). Keep the messaging encouraging ("add a Heat Shield"), not punishing.
- **Keep it deterministic.** `sim.js` stays pure; re-entry logic is gated on `state.reentering` so ascent/orbit are unaffected.
